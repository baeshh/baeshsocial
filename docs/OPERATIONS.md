# BAESH 운영 가이드

보안 통제, 모니터링, 보관 정책, 정기 점검을 정리합니다. 장애·복구 절차는 [RUNBOOK.md](./RUNBOOK.md),
요금제·계약은 [BILLING.md](./BILLING.md)를 보세요.

## 1. 보안 통제

| 영역 | 구현 |
|------|------|
| 인증·세션 | JWT에 세션 ID(`sid`)를 담고 **요청마다 DB의 세션·계정 상태를 다시 확인**합니다. 권한 변경·계정 정지·비밀번호 변경·로그아웃은 기존 토큰에도 즉시 적용됩니다. 유효기간 `SESSION_TTL_HOURS`, 미사용 만료 `SESSION_IDLE_HOURS` |
| 세션 무효화 | 비밀번호 변경 시 다른 기기 전부 로그아웃, 계정 정지 시 모든 세션 종료, 사용자는 `/settings`에서 기기별 로그아웃 |
| 조직 격리 | 모든 조직 API는 서버에서 소속·역할·조직 인증 상태를 다시 검증합니다. 승인되지 않은 조직에는 관리 기능이 없습니다. 다른 조직 자원 접근은 404/403으로 막고 `org.access_denied` 감사 기록을 남깁니다 |
| 프로그램·프로젝트 | 개인이 만든 프로젝트는 그대로 두고, 기관이 관리하는 프로젝트에만 `programId`를 연결합니다. 다른 조직 프로그램에 프로젝트를 붙이는 요청은 차단됩니다 |
| 파일 | S3 비공개 버킷(퍼블릭 차단·KMS·TLS 전용·버전 관리). 권한 확인 후 짧은 서명 URL(`FILE_URL_TTL_SECONDS`)만 발급, 다운로드는 감사 기록 |
| 검증 기록 | 업로드·외부 연동만으로는 검증되지 않습니다. 기관 담당자 승인 시 발급되고, 원본이 수정되면 검증이 해제됩니다 |
| 기업 열람 | 인재 검색은 사용자가 공개·공유를 허용한 범위만 보여 줍니다 |
| AI | 보고서 통계는 PostgreSQL 실제 데이터로 계산하고, AI는 서술 문장에만 씁니다. 근거 없는 수치·성과 문장은 검증 단계에서 제거됩니다 |
| 요청 제한 | nginx 20r/s(IP) + 앱 내부: 전체 300/분(IP), 로그인 30/15분(IP)·10/15분(계정), 가입 5/시간, 비밀번호 변경 5/15분, 업로드 60/시간, 초대 수락 30/15분, 일괄 초대 20/시간 |
| 비밀값 | SSM SecureString → `shared/backend.env`(600). 저장소·CI 로그·릴리스 묶음에 없음. 로그·감사 기록·오류 기록에서 `password/token/secret/apikey/authorization` 키는 `[redacted]` 처리. CI에서 gitleaks와 `.env` 커밋 차단 |
| 운영 설정 검사 | 운영 환경에서 기본 JWT 키, 기본 DB 비밀번호, http 프론트 주소, 로컬 파일 저장, 요청 제한 해제 중 하나라도 있으면 기동 거부 |
| 의존성 | CI가 `npm audit`(운영 의존성) high/critical을 차단. 예외는 `.github/audit-allowlist.json`에 사유·만료일과 함께만 허용 |

## 2. 감사 로그

- 기록 대상: 로그인·로그아웃·비밀번호·세션, 조직·구성원·권한·초대, 프로그램, 증빙 승인·반려·철회·파일 다운로드, 보고서 생성·다운로드, 인재 검색, 과금·계약·청구·입금, 운영자 조치(계정 정지·권한 변경·공지·문의), 접근 거부
- 항목: 시각, 수행자, 조직, 작업, 결과(성공·거부·실패), 대상, IP, User-Agent, 요청 ID, 세부(비밀값 제거)
- 조회: 플랫폼 전체 `/admin/audit`, 조직 관리자 `/org/<id>?tab=audit` (자기 조직만)
- 보관: 3년 (시간별 작업이 자동 정리)

## 3. 모니터링

| 지표 | 수집 | 확인 위치 |
|------|------|-----------|
| 요청 수·지연(평균·p95)·4xx·5xx | 앱이 경로별로 분 단위 집계 (`RequestMetric`) | `/admin/ops` 트래픽·상위 경로 |
| 서버 CPU·메모리·프로세스 RSS | `os` 모듈 | `/admin/ops` 서버 카드 |
| DB 응답·크기·연결 수 | `pg_stat_activity`, `pg_database_size` | `/admin/ops` 데이터베이스 카드 |
| 오류 | 같은 원인끼리 지문으로 묶어 횟수·최근 발생 기록 (`ErrorEvent`), Sentry(`SENTRY_DSN`) | `/admin/ops` 열린 오류 |
| 업로드 실패율 | 업로드 경로 4xx/5xx 비율 | `/admin/ops` |
| AI 호출·비용·품질 | `AIUsageLog` | `/admin/ai`, `/admin/ops` |
| 사용자 활동 | DAU·WAU·MAU, 가입 추이 | `/admin/ops` 사용량 |
| 백업·복원·파일 점검·배포 | 스크립트가 `/api/ops/runs`에 보고 (`OPS_INGEST_TOKEN`) | `/admin/ops` 백업·복구, 운영 기록 |
| 외부 가용성 | GitHub Actions `uptime.yml` 10분 간격 | 웹훅 알림 |

AWS 쪽은 CloudWatch 에이전트로 EC2 CPU·메모리·디스크, RDS 지표(CPU, 연결, 여유 저장공간)에 경보를 걸어 같은 웹훅(SNS → Chatbot/Lambda)으로 보냅니다.

### 자동 알림 (`ALERT_WEBHOOK_URL`, 같은 알림은 일정 시간 중복 발송 안 함)

| 조건 | 수준 |
|------|------|
| 최근 10분 5xx 비율 급증 | 긴급 |
| 26시간 안에 성공한 DB 백업 없음 (운영) | 긴급 |
| 35일 안에 복원 훈련 성공 없음 (운영) | 경고 |
| 24시간 AI 비용 ≥ `AI_DAILY_COST_ALERT_USD` | 경고 |
| 백업·복원 훈련·파일 점검·배포 실패 | 긴급 |
| 긴급도 "긴급" 지원 문의 접수 | 경고 |

## 4. 백업·보관 정책

| 대상 | 주기 | 보관 |
|------|------|------|
| DB 전체 덤프 | 매일 03:30 KST + 운영 배포 직전 | S3 `db/` 35일, `monthly/` 1년, 서버 최근 3개 |
| 증빙·보고서 파일 | S3 버전 관리 (실시간) | 이전 버전 90일 |
| 복원 훈련 | 매주 토요일 05:00 KST | 결과는 운영 기록에 영구 보관 |
| 요청 지표 | 실시간 집계 | 14일 |
| 해결된 오류 | — | 90일 |
| 감사 로그 | 실시간 | 3년 |

구독이 만료돼도 기관 데이터는 **자동 삭제하지 않습니다** (읽기 전용 전환).

## 5. 정기 점검

**매일** — `/admin/ops`: 배지가 모두 정상인지, 최근 백업 성공, 열린 오류, 5xx 비율
**매주** — 복원 훈련 성공·소요 시간, 파일 점검 결과, 지원 문의 처리 대기, 30일 내 만료 기관(`/admin/billing`)
**매월** — 미수금·연체 청구서, AI 비용 추이, 감사 로그의 거부 기록 급증 여부, 릴리스·백업 용량
**분기** — 알림 훈련, 수동 DB 복원 리허설(RUNBOOK 4장), `audit-allowlist.json` 만료 항목 정리, 비밀값 교체(JWT_SECRET 교체 시 전체 재로그인)
