# BAESH 요금제·계약·청구

## 1. 요금제 (초기값)

가격은 사업계획 기준 가정치이며 `/admin/billing`에서 배포 없이 수정합니다. 기관 요금제는 VAT 별도입니다.

| 요금제 | 대상 | 가격 | 주요 한도 |
|--------|------|------|-----------|
| 개인 Free | 개인 | 무료 | AI 하루 10회, AI 포트폴리오 월 3회(웹 보기만) |
| 개인 Pro | 개인 | 월 8,900~29,000원 | AI 하루 100회, 포트폴리오 월 50회, PDF 내보내기 |
| 기관 체험 | 승인된 기관 (자동) | 무료, 60일 | 구성원 120, 프로그램 2, 프로젝트 20, 5GB, 보고서 5회 |
| University | 대학 | 학기당 5,000,000원 | 구성원 600, 프로그램 5, 프로젝트 120, 50GB, 보고서 학기당 30회 |
| Institution | 공공기관·재단 (대학도 가능) | 연 10,000,000원 | 구성원 2,000, 프로그램 30, 프로젝트 500, 200GB, 보고서 연 200회 |
| Enterprise | 기업 | 별도 협의 | 채용 담당자 20명, 인재 검색 월 1,000회, AI 하루 500회 |

한도 항목: 활성 구성원, 운영 중 프로그램, 프로그램 프로젝트, 저장공간(증빙·보고서), 계약 기간 내 결과보고서,
최근 30일 인재 검색, 최근 24시간 AI 호출. 계약마다 `limitOverrides`로 개별 조정할 수 있습니다.
**사용량은 항상 PostgreSQL의 실제 데이터로 계산합니다.**

## 2. 데이터 구조

```
Organization ─┬─ Subscription ── Plan          (기간·상태·유예일·한도 조정)
              ├─ Contract                      (계약번호 CT-YYYYMM-NNNN, 금액, 기간, 계약서 PDF는 비공개 저장소)
              ├─ Invoice ── Payment            (청구번호 INV-YYYYMM-NNNN, 공급가·VAT, 세금계산서 번호, 입금 기록)
              └─ UsageRecord                   (일별 사용량 스냅샷 — 추이·정산 근거)
```

## 3. 이용 상태와 제한

| 상태 | 조건 | 새 항목 생성 | 기존 자료 |
|------|------|--------------|-----------|
| `active` | 이용 기간 안 | 가능 | 조회·다운로드 |
| `past_due` | 납부 기한이 지난 청구서가 있음 | 가능 (경고 표시) | 조회·다운로드 |
| `grace` | 기간 종료 후 유예일 이내 | **불가** | 조회·다운로드 |
| `expired` | 유예일까지 지남 | **불가** | 조회·다운로드 |
| `none` | 구독 없음 | **불가** | 조회·다운로드 |

- 데이터는 만료돼도 **자동 삭제하지 않습니다.** 갱신하면 그대로 이어서 씁니다.
- 막힌 요청은 HTTP **402**와 `details.code`로 응답합니다.
  - `subscription_inactive` — 이용 상태 때문에 생성 불가 (`state` 포함)
  - `plan_limit` — 한도 초과 (`metric`, `limit`, `used`, `requested` 포함)
  - `plan_feature` — 요금제에 없는 기능 (예: Free의 포트폴리오 PDF)
- 적용 위치: 프로그램 생성·활성화, 참여자·구성원 추가, 프로젝트 연결, 증빙 업로드(저장공간), 보고서 생성, 인재 검색, AI 호출.
- `BILLING_ENFORCEMENT=warn`이면 차단하지 않고 경고만 남깁니다 (파일럿용).
- 한도의 80%를 넘으면 기관 화면에 경고, 100%면 긴급 배너가 뜹니다.

## 4. 계약부터 입금까지 (운영자)

`/admin/billing`에서 기관을 선택한 뒤:

1. **새 구독 적용** — 요금제·시작일·종료일·유예일. 기간이 겹치는 기존 구독(체험 포함)은 자동으로 정리됩니다
   (먼저 시작한 구독은 새 시작일에 종료, 나중에 시작한 구독은 취소). 기관 관리자에게 알림.
2. **계약 등록** — 계약명·금액(공급가)·기간·정산 담당자·세금계산서 수신 이메일·사업자등록번호. 서명본 PDF 업로드.
3. **청구서 작성** → 초안 확인 → **발행** (세금계산서 번호 입력 가능). 발행 시 기관 관리자에게 앱 알림 (세금계산서·청구서 PDF 발송은 회계 시스템에서 별도 진행).
4. **입금 기록** — 금액·입금일·입금자명. 전액이 들어오면 청구서는 `납부 완료`, 미납 상태였던 구독은 `active`로 복귀.
5. 잘못된 청구서는 사유와 함께 **취소**(VOID), 잘못된 입금 기록은 입금 취소.

모든 단계는 감사 로그(`billing.*`)에 남습니다.

## 5. 자동 처리 (매시간)

| 작업 | 내용 |
|------|------|
| 연체 처리 | 납부 기한이 지난 `발행` 청구서 → `연체`, 연결된 구독 → `past_due` |
| 만료 예고 | 종료 30·14·7·1일 전 기관 관리자에게 알림·메일 (각 1회) |
| 유예·만료 | 종료 시 유예 안내, 유예 종료 시 구독 `expired` 전환 및 안내 |
| 사용량 스냅샷 | 기관별 하루 단위 `UsageRecord` 갱신 |

## 6. 갱신·만료 정책

- **같은 요금제로 갱신**: 현재 기간 종료일 다음부터 새 기간이 시작됩니다 (남은 기간 손실 없음).
- 요금제 변경(업그레이드)은 새 구독 적용으로 즉시 바꿉니다. 한도는 바로 반영됩니다.
- 유예 기간 기본값: 체험 14일, 정식 계약 30일.
- 만료 후에도 기관 관리자는 결과보고서·증빙을 내려받을 수 있습니다. 학생 개인의 검증 기록은 기관 계약과 무관하게 유지됩니다.

## 7. 기관 온보딩

1. 기관 등록 → 인증 서류 제출 → 운영팀 승인 (승인 전에는 관리 기능 없음) → 체험 구독 자동 생성
2. **도입 가이드** 탭의 체크리스트를 따라 진행 (완료 여부는 실제 데이터로 판단)
3. **초대** 탭: 담당자 초대 → 프로그램 생성 → 학생 CSV 일괄 초대(이메일·이름·학번·학과·역할, 한글 헤더 지원)
   - 초대 링크는 해당 이메일 계정으로만 수락 가능, 유효기간 `INVITE_TTL_DAYS`
   - 프로그램을 지정하면 수락과 동시에 참여자로 등록
   - 구성원 한도를 넘는 초대는 거부
4. 프로그램에서 프로젝트를 만들고 학생 배정 → 학생 활동 기록 → 담당자 승인 → 결과보고서 발급
5. **요금제·사용량** 탭에서 기간·한도·계약·청구서 확인, **감사 로그** 탭에서 조직 내 작업 기록 확인
6. 문의는 `/support` (조직 관리자는 조직 명의로 등록), 운영팀 공지는 화면 상단 배너로 표시
